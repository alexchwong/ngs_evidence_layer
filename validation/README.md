# NEL validation cases

This directory contains the standalone validation corpus used to test NGS Evidence Layer behaviour.

- `case_summary.md` contains the existing general validation suite.
- `case_functional.md` contains the parallel function-targeted suite used by `nel-validate-function`.
- `case_functional_manifest.md` describes the purpose of every functional case and is evaluator/developer-only; it is never a runtime model input.
- `cases.py` provides helpers to retrieve case inputs and marking criteria.
- `prompts/workflow/mark_validation_report.md` is the template used to generate the external categorical marking prompt.
- Marking criteria are evaluator-only and must not be supplied to NEL before `report-final.md` is complete.

Typical Python usage:

```python
from validation.cases import retrieve_case, retrieve_MC
retrieve_case("1")   # shared stem only
retrieve_case("1A")  # shared stem + variant clinical information
retrieve_MC("1A")    # evaluator marking criteria only
```

Command-line usage:

```bash
# List all available case IDs
python validation/retrieve_cli.py list
# List function-targeted case IDs
python validation/retrieve_cli.py list --file validation/case_functional.md
# Retrieve clinical information for a case variant
python validation/retrieve_cli.py case 1A
# Retrieve a function-targeted case
python validation/retrieve_cli.py case 1A --file validation/case_functional.md

# Retrieve shared stem only (Case 1)
python validation/retrieve_cli.py case 1

# Retrieve marking criteria
python validation/retrieve_cli.py MC 1A

# Help
python validation/retrieve_cli.py --help
python validation/retrieve_cli.py case --help
python validation/retrieve_cli.py MC --help
python validation/retrieve_cli.py list --help
```

`nel-validate <case-id>` retrieves only clinical case content before report generation. Step 7 does not mark in the same model session. It creates two separate archives: `validation/package_marking.py` builds the external-marking ZIP containing only `marking-prompt.md`, `validation-case.md`, and `report-final.md`, while `scripts/package_run.py` builds `ngs-report-debug.zip` containing every artifact generated by the full reporting workflow. The generated marking prompt embeds the case-specific criteria. `evidence.md` is intentionally excluded from the marking ZIP but retained in the debug ZIP.

`nel-validate-function <case-id>` uses the same report-generation pipeline as `nel-validate`,
but retrieves from `case_functional.md` and calls `package_marking.py --case-file
validation/case_functional.md`. Its external bundle is named
`nel-validation-function-<case-id>.zip`. The functional manifest is not read or packaged.
