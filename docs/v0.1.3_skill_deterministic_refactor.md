# v0.1.3 Skill Deterministic Refactor — Technical Specification

## 1. Purpose

Refactor the `ngs_evidence_layer` case workflow so that the language model performs only the two decisions that require interpretation:

1. **Step 1:** read the supplied case prose and create `case-input.json`.
2. **Step 3:** read `prompts/diagnostic_adjudication_prompt.md` and `step2.json`, then create `adjudication.json`.

All other work must be performed by deterministic scripts.

The terminal artifact of this skill is `block.md`. Production of a downstream interpretative report is out of scope.

This specification targets the repository branch:

- Repository: `alexchwong/ngs_evidence_layer`
- Baseline branch: `v0.1.3-devel`

## 2. Goals

1. Minimise model discretion outside Steps 1 and 3.
2. Remove manual copying of `genes` and `provisional_disease` into command arguments.
3. Use invariant corpus and index locations by default.
4. Provide a deterministic wrapper for Steps 2, 4, and 5.
5. Use a secure system temporary directory when the user does not provide a working directory.
6. Print the selected working directory before Step 1 begins.
7. Deliver `block.md` as the sole final artifact.
8. Preserve an exact, machine-readable relationship between every rendered evidence card and its primary and secondary references.
9. Place card-to-reference mappings at the end of `block.md`, publication-style, rather than inline with evidence statements.
10. Preserve the existing retrieval, validation, ordering, collapsing, citation numbering, truncation, and failure-closed behaviour unless explicitly changed below.

## 3. Non-goals

The refactor must not:

- perform report synthesis;
- retain or replace current Step 6;
- add model decisions after Step 3;
- introduce live literature or database retrieval;
- alter corpus ingestion;
- change disease filtering semantics;
- change adjudication semantics or its JSON contract;
- duplicate citation-allocation logic in `run_case.py`;
- allow the wrapper to infer or repair invalid model output;
- delete advanced command-line overrides from `retrieve.py`.

## 4. Resulting workflow

```text
User case prose
    |
    | Step 1 — bounded LLM decision
    v
<work-dir>/case-input.json
    |
    | python scripts/run_case.py diagnosis --work-dir <work-dir>
    | deterministic wrapper -> retrieve.py diagnosis
    v
<work-dir>/step2.json
    |
    | Step 3 — fresh bounded LLM decision
    | reads only diagnostic_adjudication_prompt.md + step2.json
    v
<work-dir>/adjudication.json
    |
    | python scripts/run_case.py full --work-dir <work-dir>
    | deterministic wrapper -> retrieve.py full -> render.py
    v
<work-dir>/bundle.json
<work-dir>/block.md
    |
    | skill returns block.md as the sole artifact
    v
Done
```

There is no Step 6.

## 6. Working-directory contract

### 6.1 Selection

Before Step 1, the skill must select the working directory.

Selection order:

1. If the user supplies a directory, use that directory.
2. Otherwise, create a unique directory using the host platform's secure system-temporary-directory facility.

The default must not be a repository-local directory such as `work/`, the current directory, or a hard-coded `/tmp/...` path.

For Python implementations, use `tempfile.mkdtemp()` or `tempfile.TemporaryDirectory()` semantics. Because the directory must remain available after the wrapper exits, the skill should create and retain it rather than use an automatically deleted context manager.

### 6.2 Required announcement

The skill must print the absolute resolved directory before reading the case for Step 1.

Required form:

```text
Working directory: /absolute/path/to/directory
```

This is workflow status output, not an artifact.

### 6.3 Retention

- Retain the directory after success.
- Retain the directory after failure.
- Do not perform automatic cleanup.
- A future explicit cleanup option may be added, but it is not required by this refactor.

### 6.4 Safety

The skill and wrapper must:

- resolve the directory to an absolute path;
- create it if necessary;
- fail if the path exists but is not a directory;
- fail on unreadable or unwritable directories;
- never silently fall back to another directory after the selected path has been announced.

## 8. `retrieve.py diagnosis` refactor

### 8.1 New primary interface

Add a required primary input accepting the complete Step 1 document:

```bash
python scripts/retrieve.py diagnosis \
  --case-input <work-dir>/case-input.json \
  --output <work-dir>/step2.json
```

`retrieve.py diagnosis` must extract and validate:

- `genes`;
- `provisional_disease`;
- `case_facts`.

### 8.2 Default corpus and index paths

Retain these invariant defaults:

```text
output/corpus/nel.corpus.json
output/corpus/nel.index.json
```

Resolution must be repository-root-safe rather than dependent on the caller's current working directory.

Recommended implementation:

```python
REPO_ROOT = Path(__file__).resolve().parent.parent
DEFAULT_CORPUS = REPO_ROOT / "output/corpus/nel.corpus.json"
DEFAULT_INDEX = REPO_ROOT / "output/corpus/nel.index.json"
```

Store resolved paths in `step2.json` so `retrieve.py full` can continue to load the same immutable inputs.

### 8.3 Advanced overrides retained

Retain the existing options as advanced overrides:

- `--genes`;
- `--provisional-disease`;
- `--corpus`;
- `--index`.

The legacy `--case-facts` option may also remain for backward compatibility, but it is not part of the new skill path.

### 8.4 Override precedence

Use deterministic field-level precedence:

1. explicit command-line override;
2. value from `--case-input`;
3. existing default, only where one is semantically valid.

Specifically:

| Value | Explicit override | Case input | Default |
|---|---:|---:|---:|
| genes | `--genes` | `case-input.json.genes` | none; fail if absent |
| provisional disease | `--provisional-disease` | `case-input.json.provisional_disease` | existing unspecified disease default only for legacy invocation without `--case-input` |
| case facts | `--case-facts` | `case-input.json.case_facts` | empty list only for legacy invocation |
| corpus | `--corpus` | n/a | invariant corpus path |
| index | `--index` | n/a | invariant index path |

When `--case-input` is used, a missing `provisional_disease`, `genes`, or `case_facts` field is an error. The script must not silently apply legacy defaults to malformed Step 1 output.

### 8.5 Input validation

For `--case-input`, require:

- a JSON object;
- exactly the required top-level fields, unless the repository deliberately permits forward-compatible extra fields elsewhere;
- `provisional_disease` as a valid disease-vocabulary value;
- `genes` as a non-empty JSON array of non-empty strings;
- no duplicate genes after case-insensitive normalisation;
- `case_facts` as an array accepted by existing `validate_case_facts()`;
- unique, non-empty `fact_id` values.

Normalise genes using the existing uppercase retrieval convention. Do not alter variant or case-fact content.

### 8.6 Conflicting inputs

When `--case-input` and an advanced override are both supplied, the explicit override wins. The script should emit a concise stderr notice naming each overridden field, for auditability.

Example:

```text
[retrieve] overriding case-input genes from --genes
```

Do not compare values semantically or ask for confirmation.

### 8.7 Backward compatibility

The existing invocation must continue to work:

```bash
python scripts/retrieve.py diagnosis \
  --genes SF3B1 \
  --provisional-disease "myeloid neoplasm, unspecified" \
  --case-facts case-facts.json \
  --corpus output/corpus/nel.corpus.json \
  --index output/corpus/nel.index.json \
  --output step2.json
```

The new skill must use `--case-input`, not the legacy form.

## 9. `run_case.py` wrapper

### 9.1 Responsibility

`scripts/run_case.py` is a thin deterministic orchestrator. It must not implement retrieval, adjudication, rendering, citation numbering, card collapsing, or output post-processing.

It invokes the canonical scripts as subprocesses and fails closed on any non-zero exit status.

### 9.2 Subcommands

Provide exactly two workflow subcommands:

```text
run_case.py diagnosis
run_case.py full
```

### 9.3 Common option

```text
--work-dir PATH
```

For direct command-line use, `--work-dir` should be optional. If omitted, `run_case.py` creates a retained secure system temporary directory and prints its absolute path to stderr before running any child process.

The skill will normally select and announce the directory before Step 1, then pass it explicitly to both wrapper calls.

Optional advanced Python-interpreter override:

```text
--python PATH
```

Default: `sys.executable`.

### 9.4 `run_case.py diagnosis`

#### Inputs

Required file in the working directory:

```text
case-input.json
```

Optional advanced path overrides may be exposed and forwarded:

- `--case-input PATH`;
- `--output PATH`;
- `--genes ...`;
- `--provisional-disease VALUE`;
- `--corpus PATH`;
- `--index PATH`.

Defaults:

```text
--case-input <work-dir>/case-input.json
--output     <work-dir>/step2.json
```

#### Child command

Construct an argument array, not a shell string:

```bash
<python> scripts/retrieve.py diagnosis \
  --case-input <work-dir>/case-input.json \
  --output <work-dir>/step2.json
```

Forward only explicitly supplied advanced overrides.

#### Output

```text
<work-dir>/step2.json
```

The wrapper must verify that the child exited successfully and that the expected output file exists and is a regular file.

### 9.5 `run_case.py full`

#### Inputs

Required files in the working directory:

```text
step2.json
adjudication.json
```

Optional advanced path overrides:

- `--diagnosis-result PATH`;
- `--adjudication-result PATH`;
- `--bundle-output PATH`;
- `--output PATH` for `block.md`;
- `--genes ...`;
- `--corpus PATH`;
- `--index PATH`;
- `--token-budget INTEGER`.

Defaults:

```text
--diagnosis-result    <work-dir>/step2.json
--adjudication-result <work-dir>/adjudication.json
--bundle-output       <work-dir>/bundle.json
--output              <work-dir>/block.md
```

#### Child command 1 — Step 4

```bash
<python> scripts/retrieve.py full \
  --diagnosis-result <work-dir>/step2.json \
  --adjudication-result <work-dir>/adjudication.json \
  --output <work-dir>/bundle.json
```

Forward only explicitly supplied advanced retrieval overrides.

#### Child command 2 — Step 5

Run only after Child command 1 succeeds and `bundle.json` exists:

```bash
<python> scripts/render.py \
  --bundle <work-dir>/bundle.json \
  --output <work-dir>/block.md
```

Forward `--token-budget` when explicitly supplied.

#### Output

The terminal output is:

```text
<work-dir>/block.md
```

`bundle.json` remains an internal deterministic intermediate.

### 9.6 Subprocess requirements

- Use `subprocess.run(..., check=True)` or equivalent.
- Do not use `shell=True`.
- Use repository-root-resolved script paths.
- Preserve child stdout and stderr unless tests require capture.
- On failure, return a non-zero exit status.
- Identify the failed stage in the wrapper error.
- Do not continue to rendering after retrieval failure.
- Do not edit a child output.
- Do not catch and convert failures into successful partial output.

### 9.7 Existing-output policy

Default behaviour: deterministic overwrite through the existing child script interfaces.

The wrapper must not delete valid inputs before execution. It may overwrite:

- `step2.json` during `diagnosis`;
- `bundle.json` and `block.md` during `full`.

It must never overwrite:

- `case-input.json`;
- `adjudication.json`.

### 9.8 Wrapper status output

Status messages go to stderr and may include:

```text
[run_case] working directory: /absolute/path
[run_case] step 2: retrieve diagnosis evidence
[run_case] step 4: retrieve full evidence bundle
[run_case] step 5: render evidence block
[run_case] output: /absolute/path/block.md
```

Status output must not be written into JSON or Markdown artifacts.

## 11. `render.py` refactor

### 11.1 Reason for modifying `render.py`

The current renderer collapses byte-identical interpretations and attaches the union of all citation numbers to the collapsed line. Its public text and JSON results do not preserve which individual card contributed which primary or secondary reference.

A wrapper cannot safely reconstruct that mapping without duplicating renderer internals. Therefore `render.py` must own and emit the mapping.

### 11.2 Evidence-body format

Remove inline card IDs and citation markers from evidence statements.

Current form:

```text
[C1-1, C1-2] Interpretation text. [1,2]
```

Required form:

```text
Interpretation text.
```

Retain existing:

- category headings;
- card ordering before collapse;
- byte-identical interpretation collapsing;
- wrapping rules;
- evidence-tier truncation rules.

Each rendered fact line remains traceable through an end-of-document mapping.

### 11.3 Citation numbering

Retain deterministic numbering by first appearance in the final rendered card set.

For every rendered card, assign:

- exactly one primary reference number;
- zero or one secondary reference number under the current card schema.

The implementation should support arrays internally so future schemas can carry more than one reference of either kind without changing the output data model.

### 11.4 Required internal line data

After collapsing and numbering, each rendered line must retain at least:

```json
{
  "category": "diagnosis",
  "interpretation": "...",
  "card_ids": ["C1-1", "C1-2"],
  "card_reference_map": [
    {
      "card_id": "C1-1",
      "primary_refs": [1],
      "secondary_refs": []
    },
    {
      "card_id": "C1-2",
      "primary_refs": [1],
      "secondary_refs": [2]
    }
  ]
}
```

Do not derive the per-card map from the collapsed union. Assign numbers directly while iterating each member's `citation_entries()`.

### 11.5 End-of-document card mapping

Add a section immediately before the numbered bibliography:

```markdown
## Refs

C1-1,C1-2,C1-5: primary ref 1
C1-3: primary ref 1; secondary ref 2
C2-1: primary ref 2

## References

1. First publication citation.
2. Second publication citation.
```

The heading must be exactly:

```text
## Refs
```

The bibliography heading remains:

```text
## References
```

### 11.6 Grouping rules for `## Refs`

Cards may share one mapping line only when their complete ordered reference signature is identical.

Reference signature:

```text
(primary_refs, secondary_refs)
```

Examples:

- Cards with `primary_refs=[1]`, `secondary_refs=[]` may be grouped.
- A card with `primary_refs=[1]`, `secondary_refs=[2]` must be on a separate line.
- A card with primary ref 2 and secondary ref 1 must not be grouped with a card whose primary ref is 1 and secondary ref is 2.

Within each mapping group:

- sort card IDs using the same deterministic card order used by rendering, not arbitrary dictionary order;
- join card IDs with commas and no spaces, matching the requested publication-style form.

Order mapping lines by the earliest rendered occurrence of any member card. Use card ID as the final deterministic tie-breaker.

### 11.7 Mapping-line grammar

Required grammar:

```text
<card-id-list>: primary ref <n>[,<n>...][; secondary ref <n>[,<n>...]]
```

Examples:

```text
C1-1,C1-2,C1-5: primary ref 1
C1-3: primary ref 1; secondary ref 2
C2-1: primary ref 2
```

Use singular labels `primary ref` and `secondary ref` even when multiple numbers are present, unless a later style decision explicitly changes this.

A rendered card must never have an empty primary reference list. Missing citation metadata still receives a numbered placeholder reference using existing renderer behaviour.

If no cards are rendered:

```markdown
## Refs

None; no cards were rendered.
```

### 11.8 Relationship to collapsed facts

A collapsed interpretation can correspond to multiple mapping lines when its member cards have different reference signatures. This is intentional.

The downstream prose generator can:

1. identify the card IDs associated with a fact from structured renderer output;
2. resolve each card through `card_reference_map`;
3. cite the correct numbered bibliography entries.

To support this reliably, JSON output must retain both fact-to-card and card-to-reference relationships.

### 11.9 JSON output additions

For `--format json`, retain all current fields and add:

```json
{
  "rendered_facts": [
    {
      "category": "diagnosis",
      "interpretation": "Interpretation text.",
      "card_ids": ["C1-1", "C1-2"]
    }
  ],
  "card_reference_map": [
    {
      "card_ids": ["C1-1", "C1-2", "C1-5"],
      "primary_refs": [1],
      "secondary_refs": []
    },
    {
      "card_ids": ["C1-3"],
      "primary_refs": [1],
      "secondary_refs": [2]
    }
  ]
}
```

Requirements:

- `rendered_facts` contains only facts that remain after truncation.
- `card_reference_map` contains only cards that remain after truncation.
- Every `card_id` in `rendered_facts` appears exactly once across `card_reference_map[*].card_ids`.
- Every number in the map exists in `references[*].number`.
- `references[*].kind` remains available.
- The text representation and structured representation must be generated from the same in-memory data.

### 11.10 Truncation and numbering

Citation numbering and the `## Refs` map must be recalculated after every truncation pass.

Dropped cards must not appear in:

- evidence statements;
- `rendered_facts`;
- `card_reference_map`;
- `## Refs`;
- the numbered bibliography, unless the same reference remains used by a retained card.

The token estimate must include both `## Refs` and `## References`.

## 13. Error handling

All components fail closed.

### 13.1 Step 1 errors

Stop when:

- the case is missing or unreadable;
- disease vocabulary is missing or unreadable;
- the working directory cannot be created or written;
- valid `case-input.json` cannot be produced.

### 13.2 Diagnosis wrapper errors

Stop when:

- `case-input.json` is absent, malformed, or invalid;
- corpus or index is absent or stale;
- retrieval fails;
- `step2.json` is not produced.

### 13.3 Step 3 errors

Stop when:

- prompt or `step2.json` is absent or unreadable;
- adjudication output is not valid JSON;
- required output fields cannot be produced without adding knowledge.

Validation remains authoritative in `retrieve.py full`.

### 13.4 Full wrapper errors

Stop when:

- `step2.json` or `adjudication.json` is missing;
- adjudication validation fails;
- full retrieval fails;
- `bundle.json` is not produced;
- rendering fails;
- `block.md` is not produced.

Never return an older `block.md` after a failed run. To prevent stale-file confusion, `run_case.py full` should remove or atomically replace only its own expected output files before/while executing. Preferred implementation is child output to a temporary sibling file followed by `Path.replace()` after success, where compatible with existing script interfaces.
